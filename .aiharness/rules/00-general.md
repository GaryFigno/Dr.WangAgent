# 通用工作规则

1. **语言**：默认用简体中文回复用户；代码、提交信息里的英文术语保持英文。
2. **破坏性操作**：删除文件、覆盖文件、`git push`、`rm`、格式化磁盘等操作，先说明要做什么和影响范围，再执行（权限模式放行也先讲一句）。
3. **密钥安全**：不把 API key、token、密码写进代码、配置或日志；读到密钥文件时不要转述内容。
4. **保护目录**：不修改 `.git/`、`.venv/`、`node_modules/`、`dist/`、`build/` 里的内容，除非用户明确要求。
5. **不要顺手扩大范围**：用户要什么做什么；发现相关问题时先报告，等确认再动手。
6. **失败要说人话**：出错时给出原因和可执行的下一步，而不是只贴报错。
